# 番时记 · 日本新番日历

个人使用的本机网页工具，使用 Vue 3、TypeScript、Vite 和 Node.js / Express。提供本周番表、季度目录、作品详情、追番收藏，以及 JSON 备份。

V3「光帧日历」以作品封面、渐变光场和日历排版组织四个页面，支持浅深双主题、桌面顶部导航和手机浮动底栏。主视觉切换联动海报、背景与文字，卡片提供细线高光、轻微倾斜和收藏反馈，并支持减少动态效果。

本周番表支持竖列/横排切换；季度目录在宽屏可选择每行4、5、6部并记住偏好，窄屏自动调整。少量追番采用横向卡片，突出下次放送；较多追番采用海报网格。卡片显示有效Bangumi评分，详情提供评分人数及排名。

## 从源码开始

需要 Node.js 24.19 或更高的24系列版本和 npm。在终端执行：

```powershell
git clone https://github.com/KONOK-A/Anime-Calendar.git
cd Anime-Calendar
npm ci
npm run build
.\start.cmd
```

依赖、构建结果及本地缓存不纳入仓库。首次安装需要联网，后续日常使用可直接双击启动。

## 使用

双击项目根目录的 **start.cmd**，浏览器会打开 **http://127.0.0.1:4317**。保持启动窗口打开；关闭该窗口或按 Ctrl+C 会停止服务。关闭网页不会停止服务，再次双击可打开已有实例。

工具只绑定本机地址，不提供局域网访问。不要改用 localhost 或其他端口：浏览器收藏与网站地址绑定。若4317被其他程序占用，会明确报错，不会自动换端口。

主题默认跟随系统，也可在顶栏选择浅色或深色，之后记住选择。季度、搜索、分页、番表日期及滚动位置在当前标签页内保留，刷新后也能恢复，关闭标签页后重置。手机横排还按日期、时区和收藏筛选保留横向位置，切换视图或从详情返回后恢复。追番收藏仍长期保存在当前地址，不随标签页关闭清空。

日常启动直接使用已构建产物。若依赖/构建被移除，先在本目录运行：

```powershell
npm ci
npm run build
```

要求 Node.js 24.19 或更高的24系列版本。首次获取数据需要联网；以后优先展示项目内缓存，距最近成功获取超过六小时才在启动时后台刷新。页面也有“刷新数据”；保持打开期间不会周期刷新。

数据请求复用已有 HTTP_PROXY / HTTPS_PROXY 环境变量；未提供时会只读查询 Windows 已启用的手动HTTP系统代理。不会修改系统代理或关闭TLS校验。自动代理脚本/PAC和仅SOCKS配置不做自动解析，可使用已有HTTP代理环境变量。

## 功能与时间含义

- 本周番表包含有当前在播依据的跨季作品。宽屏七列，小于1200px时选择单日查看。
- 季度目录提供数据源已收录的日语TV/Web历史，支持中文/日文/别名搜索、类型筛选和24条分页；历史目录不保证完整。
- 默认北京时间，可切换日本时间；季度固定按来源begin的北京时间归类，不随显示时区改变。
- 网络先行作品默认采用网络平台播出时间，番表标明“网络先行”和平台。详情同时列出采用的平台、地区及原放送参考；季度归属不随网络提前开播而改变。
- 正常数据从明确的onair平台周期识别先行；已核实的官网修正优先，排除旧季共用页面、条目建档日期和首集特别播出的错误周期。官方“平台先行”有时晚于AT-X或其他电视，本工具仍按网络时刻显示。
- 周期排期直接显示参考时间；“来源排期”表示单次/首播记录，“公告”表示带一手来源的人工单次修正。排期时间早于当前时间不代表平台已更新。
- 仅自动展开一次性、日播和周播规则；其他周期进入待定说明。已知结束日期和休播/改档优先于来源周期。
- 集数是条目收录信息，不是已更新集数；平台地区和可播放性以平台为准。
- 有对应平台记录的作品会自动显示“巴哈姆特动画疯（台湾）”及“巴哈姆特动画疯（港澳）”入口，保留作品链接与来源地区；无关联记录时不添加通用首页链接冒充上架记录。
- 详情页展示已收录的导演、副导演、系列构成、编剧、人设原案、动画人设、音乐、动画制作等主创资料，以及主角和配角的对应CV。默认显示前8名角色，其余可展开；没有收录的CV明确标注，不根据演员名单猜配角色。
- 带独立“简介原文/原文”标记的内容默认折叠，点击“简介原文”展开；中文正文保持可见。没有明确标记的简介保留全文，避免误折叠仅有的故事介绍。

## 收藏与备份

收藏保存在当前浏览器 localStorage，多标签页同步。清除浏览器数据、切换浏览器或网站地址不会自动迁移收藏。

在“我的追番”导出JSON备份。导入采用合并去重；无效文件不会改变原收藏。不在当前目录中的ID仍保留，可导出或移除；目录暂时不可用时也能备份。

## 缓存与人工修正

`.local` 保存源目录、当前放送名单及详情缓存。详情按需要获取并缓存24小时。上游请求最多两个并发，各来源独立记录成功时间，失败保留有效旧数据，超过24小时显示过期提示。

制作阵容与CV通过Bangumi条目infobox、关联人员和角色接口自动获取。关联人员/角色仅在打开详情页时请求，独立缓存24小时；旧详情缓存可直接补读已有infobox，无需清空缓存。单一补充来源失败时仍展示其余资料和有效旧数据，并提供重试入口。

角色名优先使用角色条目收录的“简体中文名”，再用其他中文名，未收录时保留原名；可通过角色链接的提示查看原名。中文角色详情同样缓存24小时：默认只补前8名，展开其余角色后再分批获取，所有请求仍共享两个并发名额。制作人员与CV姓名保留源站写法，不自行翻译。

`data/overrides.json` 是人工修正记录，自动更新不覆盖。修改后重新启动服务生效，格式版本为1：

- `active`：`animeId`、`active`、`sourceUrl`，补充/取消在播依据。
- `events`：`animeId`、`at`（带时区的ISO时间）、`status`（scheduled/cancelled）、`sourceUrl`、可选`originalAt`和`note`。改档填写原时刻和新时刻，休播填写原时刻。
- `rules`：`animeId`、`broadcast`或`dateOnly:true`、`sourceUrl`、`note`。`kind:"network"`另需`platform`，可附`regions`和独立核实的`end`，强制采用官网网络时段；`kind:"broadcast"`可省略`broadcast`，用于屏蔽错误早播候选并继续使用上游原放送周期。既有不带kind的周期修正继续有效。

网络有自己的结束时间时优先采用；若只有原放送结束时间，且两者周期相同，则按初始提前/延迟量及当前网络周期换算预计截止，避免遗漏晚于电视的网络末集或多推算提前完结的作品。未知或不同周期不据此臆造网络结束事实，周期排期始终是预计。

已包含抽样核查中发现的隔周误记、分钟未证实，以及本季官网网络先行与错误早播记录修正。详细依据见 [数据核查](docs/data-validation.md)。

维护时可在**服务已停止**的情况下运行 `npm run data:update`；运行期间请使用网页刷新，避免两个进程同时维护缓存。

## 开发与验证

```powershell
npm run typecheck
npm test
npm run build
npm run test:e2e
```

浏览器测试使用本机 Chrome，测试服务仅在127.0.0.1:4321运行，使用独立临时目录与固定测试数据，不写入实际目录缓存或个人收藏。生产服务使用4317。修改源代码后重新构建再启动；`npm run dev`可运行Vite开发页面，API需要本地服务同时运行。

Vue类型检查使用TypeScript6.0.3与vue-tsc，服务端单独执行tsc。依赖由package-lock.json锁定，不需要安装全局包。
